Redis design system · 20 patterns

Ask Claude for an HTML artifact that's actually worth reading.

A library of twenty prompts that ask Claude to produce single-file HTML artifacts instead of walls of markdown. Each prompt names the structural primitives (annotated diffs, side-by-side grids, draggable cards, live demos) and includes an export button that closes the loop back to text. Pair this page with a Claude Project that has the Redis design system in its knowledge — the design context lives there, so the prompts stay short and reusable.

Setup

Two ways to use this

Pick one. The first is cleaner and what these prompts assume; the second is the no-account-required fallback.

Recommended

Claude Project (paid plans)

One-time setup. The design system lives in the project's knowledge base; every chat inside the project applies it automatically.

  1. Download the project bundle redis-project-bundle.zip from the post that accompanied this page.
  2. In claude.ai, create a new Project ("Redis-styled HTML artifacts" or similar).
  3. Upload tokens.css, styles.css, and the four reference HTMLs to project knowledge.
  4. Paste the contents of PROJECT-INSTRUCTIONS.txt into the project's custom-instructions field.
  5. Start a new chat inside the project. Copy any prompt below. Paste. Done.

Paste-a-preamble (free, or one-off chats)

No project required. Paste the design preamble below into a fresh chat once at session start. Then paste any prompt from the library.

  1. Open a fresh Claude chat (no project needed).
  2. Copy the preamble in the next section.
  3. Paste it as your first message.
  4. From the same chat, copy any prompt below and paste it as your next message.

Design preamble

For non-project sessions

Skip this section if you're using a Claude Project. Otherwise, this is the one-time message you paste at the start of a session so the prompts below produce Redis-styled output.

Paste this once at session start

For HTML artifacts in this conversation, apply the Redis design system: Geist font for prose, Source Code Pro for code, primary blue #0070f3 for actions, slate text on white surfaces, 0.5rem button radii and 0.8rem card radii. Use BEM-ish component naming: .btn--primary, .btn--secondary-fill, .card, .badge--informative, .section-block, .input, .chip. Surface bg #ffffff, page bg #fcfcfc, borders #e9e9e9, muted text #5c707a. Reserve semantic variants (.badge--success / --attention / --notice / --danger) for actual semantic meaning, not decoration. Generate single-file artifacts with all CSS inline. When asked to produce a non-HTML response (chat answers, summaries), respond normally in markdown — Redis design applies to HTML artifacts only.

The honest check

Polished Redis-styled output can make shaky model judgments look authoritative — color-coded severity, neat diagrams, confident headings. After each generated artifact, ask: did the format help me reason about the content, or did it make me trust the answer more than it deserves? If the latter, ask Claude for the same thing as plain markdown and see if the conclusions still hold.

Built on top of the technique described in Thariq Shihipar's "The unreasonable effectiveness of HTML." Restyled with the Redis design system (themeLight2). The prompts are short by design: they assume the design context lives in your Claude Project, not in each prompt. Swap the preamble out for a different design system if you want — the pattern is portable.
